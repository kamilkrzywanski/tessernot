# Plan: pure-Java OCR

Decision log. Code, names, the CLI and all documentation are in English. User documentation is `README.md` and `docs/`.

## Goal

An OCR engine with no native libraries, in one JAR plus the model files. It should read print, invoices and ordinary scans. The performance goal is under 300–500 ms per A4 page on CPU with the Vector API. This is a threshold to measure, not a guarantee. The idea is close to lw.PPOCR (a custom runtime for PP-OCR models). The code is written from scratch and is not a port of that source.

After Phases 1–2 the engine works, but it is slower than RapidOCR4j or Tess4J, and weaker on hard documents. The advantage is no native dependencies and full control. The level of commercial libraries on heavy scans is years of models and heuristics.

## Phase 0: decisions

Scope of v1:

- Print only. Handwriting has no separate path.
- Detection, an optional 180° rotation classifier and recognition. A grid made of ruling lines, with at least two columns and two rows, goes to `OcrResult.tables()` as cells. The page text keeps its previous order. A box cut by a line in the middle is read again, separately for each piece, so the cell text may differ from the line. A price in the margin, a table without ruling lines and a three-column newspaper are not a table. Reading order merges a row when the vertical overlap with the first box of that row, divided by the smaller height, is at least 0.5. A vertical caption gets its own row. Two text columns separated by a gutter are read top to bottom, the left one first, then the right one. A right-aligned price stays in the item row. A grid with three or more columns stays as rows. A three-column newspaper is out of scope.
- Starting language: detection and angle classifier from PP-OCRv5 mobile, recognition PP-OCRv6 small (multilingual CTC, Polish is in the dictionary). Another REC model is a swap of the ONNX file and the dictionary. PP-OCRv6 small replaced latin PP-OCRv5, because on the same DejaVu print it reads the Polish characters that the other model lost. The medium variant has the same number of whole lines without errors and a much larger file, so it is not the default. Tiny and latin v3 were measured and are weaker.
- Java 21. The scalar path always works. The Vector API (`jdk.incubator.vector`) turns on only when the JVM gets `--add-modules jdk.incubator.vector`. There is no `module-info` that would hard-require the incubator. The only import of the incubator is `VectorKernels`. The rest loads that class by reflection and stays on scalar when the module is missing.
- Model: a parser of a protobuf subset reads the official ONNX into an internal graph, then optimization, optionally a binary JIR v1 (magic `JIR1`) for faster startup. Loading a JIR does not optimize a second time. Shapes are dynamic. This is not a general ONNX Runtime.
- Metrics: operator tests, CER (Levenshtein) and page time (1 warm-up + 3 runs, minimum and median). The 500 ms threshold is not announced before it is measured.
- Detection limit: longer side 2048 (previously 960), configurable. On the `dev` and `test` sets 2048 lowered the total CER from 0,050 to 0,046 and from 0,070 to 0,048: small print, dense columns and thermal receipts. It costs about 1.5 GB of heap and doubles the detection time of a large page; 960 stays as the fast mode. Rounding the side to 32 uses `Math.round` (half up). Python half-to-even can differ by 32 pixels.
- Int8 is optional and off. Weight scale per row, activation scale per tensor. Unit tested. It is not an accuracy path. It turns on only for 1×1 GEMM, when `quantize` is true.
- PDF through Apache PDFBox 3.0.5, pulled into the shaded JAR. Helvetica has no Polish glyphs, so the PDF sample is ASCII. Polish text is drawn by Java2D with the DejaVu font.
- Preprocessing as in PP-OCR / OpenCV: BGR (BufferedImage is RGB), mean/std 0.5, that is `(x/255 - 0.5) / 0.5`. Bilinear resize from the OpenCV half pixel: `src = (dst + 0.5) * scale - 0.5`. REC height 48, minimum width 320, ceiling about 4096. Right padding is zero already in the normalized tensor (gray 127.5).
- The CLS of this model has a fixed 80×160, not the old 48×192. We read the size from the model signature.
- DB closer to RapidOCR: threshold 0.35, box threshold 0.5, unclip 1.6, up to 1000 candidates, 2×2 dilation with the OpenCV anchor `(0, 0)` (expansion toward the top left corner), score mode fast, limit type max. Threshold 0.35 instead of 0.3 restores ą in “łącznie” on the receipt and adds no error on the Nixon letter or on the invoice. 0.40 already loses a correct ł in “Kłodzka”. Building the configuration rejects non-finite thresholds, a detection limit below 1, a limit type other than `max` or `min`, `maxCandidates` below 1, and a REC tensor that does not fit in an array.
- Deskew and the Sauvola threshold (k=0.2, r=128, window about 25) are implemented and off by default.
- A vertical crop (`height >= 1.5 * width`) is rotated 90° left before CLS and REC. Order: warp, optional 90° rotation, CLS, optional 180° rotation, cutting off the lighter ink band, REC. A band is dropped only when it is separated from the other by at least 20 white rows and has clearly less ink (below 1.4 times). A shorter gap stays, so a dot above a letter is not cut off. A line across the full width, at most 4 rows thick, is not a second band. Re-reading a table cell does not do this step.
- Greedy CTC: blank at index 0, collapsing repeats, the result is the mean of the probabilities of the kept steps. A second softmax is not applied when the output is already a distribution. After a colon, when blank wins and the space is second and has at least 0,35, the space stays in the text. On the invoice scan this restores the gap in both NIPs. On the Nixon letter and on the receipt it adds nothing. A few other second places also enter the text, because on these three scans each one hits only a real error: “x” instead of the multiplication sign from 0,35 (row 4,99), “ł” instead of “l” from 0,34 (zapłaty), “ł” instead of “t” from 0,15 (Wrocław, łącznie, Zapłacono), a comma instead of a period from 0,34 (one amount 90,00) and “ć” instead of “ó” from 0,15 (dziewięćdziesiąt). The capital “S” in Świat has “Ś” in second place at 0,023, and the next capital S on these scans has 0,0023, so the threshold is 0,015. The small “s” from “ś” (Codziennie, 0,007) stays. The “o” in Spółka has “ó” in second place at 0,061 and no other “o” on these scans reaches 0,04, so the threshold is 0,05. A threshold of 0,10 for “t” no longer catches anything. No other pair improves anything here.
- The comparison set has two parts. `dev` (20 documents) is used to find and fix errors, so its numbers are no longer independent. `test` (27 documents: invoices, receipts, letters, two-column pages, from Wikimedia Commons, Wikisource and digital libraries) is counted once per release and is not used for tuning. Another fix tuned on `test` uses it up and requires new documents.
- Reading order looks for the gutter as the emptiest vertical strip after shrinking the boxes by their margin (unclip), because on a low-resolution scan the columns touch with their boxes. A title above the columns closes the section. The split stays only when both sides look like columns (a common left margin, one box per row); a form with scattered fields and a column of list numbers stay in rows. On `dev` the CER dropped from 0,133 to 0,056 with no change on the three gate scans.
- Corrections are a separate profile `Corrections.POLISH`, off by default (`--corrections polish` in the CLI). The default `Corrections.NONE` is the PP-OCR pipeline with no additions: detection, angle classifier, recognition, greedy CTC, reading order and tables from ruling lines. Reason: each rule below (CTC second-place thresholds, the ink band, the lexicon, second reads of the crop, invoice labels) was measured on the same three scans on which the gate is set. General quality is measured by the held-out `bench/` set, which the rules have not seen (`docs/benchmark.md`). On the three gate scans the pipeline alone has 0 / 9 / 18 edits, and with the profile 0 / 1 / 0.
- In the `Corrections.POLISH` profile: an optional lexicon after CTC, only when `lexicon-pl.txt.gz` (sjp.pl, Apache-2.0) and `lexicon-en.txt.gz` (SCOWL) lie next to the model dictionary. The files are lowercase, unique, sorted, gzipped from `/usr/share/dict/polish` and `/usr/share/dict/words`. A token of 4 to 24 letters that is not a Polish word, not an English word and not written in all capitals gets the only form from the dictionary: one diacritic, then two, then “t” read as “ł”, then “i” read as “j”, then ó, e or o read as ć (alone or with s read as ś), then at most two l read as i or j, then a single o read as c. A digit stuck to a known word gets a space. The invoice headers Wartość, Liczba, stawki, Podpis, upoważnionej, odbioru and “2 Wysyłka” come back through this step; the gate does not count them, because they are not in the reference. A small one-letter preposition stuck to the next word is split. On the three scans it leaves Nixon unchanged. The receipt without the lists has 3 edits (Żniwna and łos; Świat comes back with the CTC threshold), and with the lists 1: ł read as k in łos stays. The abbreviation polędw is added permanently, because sjp has polędwica, and the receipt cuts the name after w, and this restores ę. The lexicon alone brings the invoice down from 12 to 5. The digit Lp stuck to the item name is dropped separately, by a second read of the crop without the narrow digit and the thin line on the left, and only when that read is the first one without this digit. What remains from the cut and the lexicon is the postal code read as t6dż, that is 3 edits. This line is read once more after a brightness threshold of 220 and stays only when the code is the same and the city has at least three characters and no digit. The threshold 220 is in the flat range 195–240, which gives Lódź. The threshold 190 turns the last letter into ż, and 245 spreads out the code itself. One edit remains, L instead of Ł. The cut alone loses “ł” and “ó” in Kłodzka. Without the word lists, the first caption without the digit stays anyway, because the shorter read differs only by the loss of these two characters. The threshold 220 does not depend on the lists, but the raw read is Lodz with a plain z. Only the lexicon turns this z into ź, because lódź is the only form. A caption in all capitals gets a form only when it is one inserted letter and one diacritic away from a single word: on the invoice ORYGNAL comes back as ORYGINAŁ, and the gate does not count this. SPRZEDAZ and DZIEKUJEMY stay, because either several words match or none. A single space in “( a)” before the closing parenthesis is dropped, so “Wystawił( a):” is read as “Wystawił(a):”; “( a )” stays. A line that is only a dot, a letter and a dot is read a second time from a crop 16 pixels wider to the left and downward, without touching the top. Only one letter stuck before the dot stays: the invoice header comes back from `.m.` to `j.m.`. The gate does not count this. A digit at the front keeps the first read. This step does not apply to table cells. A line that starts with `[`, `]` or `|`, or ends with one, is read a second time after whitening the tall columns in the outermost 16 pixels. Only the read without this one stroke from each side stays, so `[VAT (%)|` comes back as `VAT (%)`. Any other difference keeps the first caption. The gate does not count this. A line that is an amount and a short rate, on the invoice `8.13 23`, is split at the vertical line only when both pieces read back as the same tokens. The gate does not count this, because this item is not in the reference. Without these two files the lexicon is skipped. This step does not apply to table cells.
- A capital Z whose top stroke has a gap in the middle gets a black 5×5 dot right above the letter and is read a second time. The new caption stays only when the only difference is ż or ź on this Z; the letter case is taken from the first read. On the receipt this brings it from 2 to 1 edit (ł read as k in łos stays). The clean Z in SPRZEDAZ, Ziemia, Zapłacono and in “Zażółć” has no such gap, or the second read does not touch it. The dot does not depend on the word lists. This step does not apply to table cells.
- An optional city list `postal-pl.txt.gz` next to the models. It comes from the GeoNames postal codes for Poland (CC-BY-4.0). Only the codes whose towns have one spelling after stripping diacritics are kept. A line that is only a code and a name gets this spelling when the letters already match and the list does not take away a diacritic. The spaces around the code stay. 90-031 writes Łódź: the invoice with the word lists goes down from 1 to 0, and without the word lists from 2 to 0, because the raw city is Lodz with ó and a plain z. Codes shared by several places, including 62-025, are not in the list, so Kostrzyn stays. A longer line with the code in the middle, Nixon and the receipt do not change. Without the file the step is skipped. It does not apply to table cells.
- Word-list search (2026-10-17). `CtcWords` searches every unlisted greedy word again on its own CTC timesteps, with a prefix beam kept inside the word lists, and takes the best listed word of the same length when its CTC probability is at most 4 nats below the greedy word's. A letter with marks scores at least e⁻³ times its plain letter on a line that shows a mark, so one unseen mark per word fits. The lists are any language's (`OcrConfig.Builder.wordList`, `--words`); `Corrections.POLISH` adds sjp.pl and SCOWL. Both numbers were set before measuring; `dev` only confirmed them, `test` was scored once. The fixed lexicon swaps above were removed in the same change: next to the search they lost 0.4 points of word F1 on `dev` and 0.3 on `test`. Plain pipeline with the two lists: word F1 0.956 → 0.963 on `dev`, 0.930 → 0.945 on `test`.
- The REC output of this model is `[N, T, 18710]`. The input has a fixed height of 48, so a different `recHeight` is rejected at startup. The class axis is the one whose size equals the dictionary. The detection map gets a sigmoid when the values fall outside about `[0, 1.2]`.
- Dictionary: 18708 tokens, each on its own line, no line with a space. Empty lines are skipped, the character content is not trimmed, one trailing CR and a BOM are removed. `useSpaceChar` appends a space. Classes: blank + 18708 + space = 18710. The space has index 18709. The Polish characters `ĄąĘęŁłŃńÓóŚśŹźŻż` are in the file.
- One `OcrEngine` is not used in parallel from outside. An internal pool parallelizes the REC lines. The detection GEMM may split rows over the pool of the calling thread. Detection must not be called from a pool thread. REC in a worker has `pool = null` and one thread. PDF pages with many threads go separately, each with its own `fork()` without a pool, so that a worker does not hand work back to the same pool.
- API: `OcrConfig.defaults(directory)` (formerly `latin`), `Builder.corrections(Corrections)`, `OcrEngine.load` / `create`, `recognize(BufferedImage)` → text, a list of lines (score, detection score, quad, bounds) and tables from ruling lines, `recognizePdf`, `recognizeLine`. CLI: `download`, `ocr`, `bench`, `pdf`, `score`, `convert`, `ops`, `synth`, `eval`, `selfcheck`. With a non-empty grid the CLI appends `--- table N ---` and separates cells with a tab.

Base models (they live in `models/` in the repository, the SHA-256 hashes are in `ModelFiles`, and `ocr download` fetches them again):

| File | Role |
| --- | --- |
| `ch_PP-OCRv5_det_mobile.onnx` | detection, opset 14 |
| `PP-OCRv6_rec_small.onnx` | recognition, opset 11, input height 48, 18710 classes |
| `ch_PP-LCNet_x0_25_textline_ori_cls_mobile.onnx` | rotation, opset 9, input 80×160, 2 classes |
| `ppocrv6_dict.txt` | multilingual dictionary, including Polish |

Operators that must work: Identity, Add, Sub, Mul, Div, Pow, Sqrt, Erf, Conv (groups, without bias and with bias), ConvTranspose 2D, Relu, Sigmoid, HardSigmoid (alpha, beta), HardSwish, GlobalAveragePool, AveragePool, MaxPool (also `auto_pad` SAME_UPPER), BatchNormalization inference, Resize nearest, Concat, MatMul, Softmax dependent on the opset, ReduceMean, Squeeze, Unsqueeze, Transpose, Slice (attributes or inputs, also a negative step), Reshape, Shape. Additionally Constant, Cast, Flatten and Dropout as pass-through. GELU in PP-OCRv6 is composed of Erf, it is not a separate operator. An unknown operator throws `Unsupported op: NAME` together with the input shapes.

## Phase 1: runtime

Done in the package `io.github.kamilkrzywanski.ocr.internal.runtime`:

- ONNX parser and JIR write/read. A weight or signature dimension that is negative or does not fit in `int` is rejected, also when truncation to 32 bits looks like zero or like a small side. A symbolic `dim_param` stays a dynamic dimension. An opset outside the `int` range is also rejected, instead of becoming a small opset number.
- graph optimization (Identity, Conv+BN, bias Add, activation epilogue, decomposed HardSwish)
- a buffer arena with no zeroing on allocation; weights are read-only and shared between sessions
- scalar and vector GEMM, 1×1 convolution as GEMM, other convolutions directly
- a `fork()` session for workers: its own arena, a shared graph

## Phase 2: pre and post

Done:

- `Images`: BGR, resize, normalization, REC and CLS tensor, rotations, deskew, Sauvola. A BGR byte product that does not fit in `int` is rejected also when the multiplication overflows `long` and looks like a small size. A detection side after rounding to 32 that does not fit in `int` is also rejected. Rotation, warp and Sauvola with a zero side return at once, without a loop over the other dimension.
- `Geometry`: convex hull, minimum-area rectangle, polygon score, homography
- `DbPost`, `Ctc`, `Charset`, `ReadingOrder`. A detection map whose side product does not fit in the buffer is rejected also when the multiplication overflows `int` and looks like an empty map.
- `OcrEngine` ties the pipeline together
- `Tables`: a grid of ruling lines as cells. The page text and the quality gate count the same lines as before

## Phase 3: usability

Done in v1:

- swapping the REC model through configuration. A model directory path that is a file or is empty is rejected before the CLI opens an image, a PDF or a download. Missing weights in `ocr` and `bench` are reported before the image is read. An empty weight file too, with the stage name, before the parser sees a truncated protobuf. When the weight hash already matches, an orphaned `.part` file is removed and nothing is downloaded. An extra positional argument, a repeated flag and a flag that the command does not use also end in an error, before the command opens anything
- deskew and the adaptive threshold as options, off by default
- PDFBox: render a page, then the same OCR. Many pages go through a window as wide as the pool: in memory there are at most as many bitmaps as threads, and fewer when the heap is small (2026-11-14: detection and the pages in flight each wait for a share of the heap, so a long PDF on many threads no longer runs out of memory). One page uses the full detection pool. The CLI prints a page when it is ready; the `--- page N ---` header appears only with more than one page. A page number out of range is an OCR error, counted from 1. A PDF with a user password is rejected before the CLI loads the model. When the `/Encrypt` marker lies farther than 64 KiB from the end, the preflight reads the object pointed to by `startxref`, so a long xref stream also stops before the model. A PDF with an empty user password opens also when an owner password is set.
- API `recognize` / `recognizeLine` / `recognizePdf`. `OcrPool` lends a separate engine per call, so several threads read pages at once, and the text stays the same as with one engine. Since 2026-11-14 the engines of a pool share the loaded models and word lists and divide the configured thread count between them. `close` waits for calls in progress. Closing a borrowed engine removes that slot from the pool. One PDF is not split between engines
- `--json` with `ocr` and `pdf` prints one document: a page object (`text`, `lines` with `text`, `score`, `detScore`, `quad`, `bounds`, and `tables` with `bounds` and `cells`) or `{"pages":[...]}` for a PDF. `OcrJson` gives the same bytes. Timings stay on stderr
- CLI, synthetic invoice, CER, time comparison stays a local measurement (Tess4J / RapidOCR4j are not a dependency). `ocr.sh` keeps the calling directory, so a relative file path is counted from it. When `--model` is not given, the script passes the `models` directory next to itself
- `Images.read` and the CLI rotate JPEG according to EXIF Orientation. PNG and an image already in memory are not touched. TIFF and GIF with more than one image are rejected with the image count. A missing file and a directory end with a message that this is not a file. A PNG, JPEG, GIF, BMP or TIFF header wins over the string `%PDF-` in the first kilobyte, so such a file is not sent to `ocr pdf`.

## Phase 4: performance

Done in v1: Vector API on GEMM, AXPY and activations, buffer reuse, size classes for activation arrays, the line pool, parallel PDF pages with no nesting in the same pool, the int8 hook off by default.

Not promised: catching up with ONNX Runtime on convolution. The measured page time, with the protocol, is in `docs/internals.md`, and the times on the held-out set next to Tesseract and RapidOCR are in `docs/benchmark.md`.

## Risks

- GEMM and convolution in pure Java stay slower than a native runtime.
- A full list of ONNX operators is not a goal. A new model export can name a missing operator, and only then do we add it.
- Quality depends on the model and the preprocessing more than on further operators.
- On the three gate scans, after the lexicon, the second read of the postal code, the dot above the indented Z and the city list, ł read as k in łos remains. The invoice with the city list goes down to zero. Żyt comes back with this dot. Łódź comes back from the code 90-031. The ogonek in Polędw comes back with the abbreviation polędw. The digit Lp next to Ziemia Kłodzka is cut off by a second read, when a narrow digit and a line stand on the left, and the second caption is the first one without this digit. Żniwna, Biuro, Miejsce, usługi and Słownie come back with the lexicon. Świat and ó in Spółka come back also without the lexicon, because they were a CTC second place. Without the dictionary the second read adds four white rows, shifts the ink by four pixels, and then adds eight white rows underneath. The read that has the most allowed fixes stays: ł to t or l, or a space between letters. The invoice without the dictionary has 0 edits: “i magazyn” comes back, usługi, the whole Spółka with a space before Wspólnicy, the name without the digit Lp, and the labels Miejsce wystawienia and Słownie come back when the whole line is one edit from one known VAT invoice label and has no digit. The receipt without the dictionary has 3 edits. Without the dictionary and without the city list the invoice has 2 edits, because the city stays Lodz with ó and a plain z. Nixon does not change. With the dictionary the margin step is skipped. The multiplication sign, Wrocław, łącznie, zapłaty, Zapłacono, the comma in the amount, “ć” in dziewięćdziesiąt, “Ś” in Świat and “ó” in Spółka come back with CTC rules. The angle classifier does not rotate these lines. Widening the crop by a few pixels fixes part of the invoice and breaks the commas on the receipt, so the crop stays without a margin. Thickening, morphological closing and other image filters on these scans swap errors, they do not reduce them. The line between Liczba and j.m. has eighteen white rows in the letter and stays one line when both pieces are long; a shorter digit stem does not stick together like that. An overlap shorter than 28 pixels does not cut the box. A cell piece goes through the same lexicon as a line. An empty cell with ink is read once and stays only as a short number or a short word: on the invoice the one in Liczba and the header Lp come back. When a vertical line enters a box by at least 20 pixels, but too shallowly to cut it, the cell interior stays if it differs only in letter case: “Szt.” in the cell is “szt.”. The line does not change.
- Black text on a white background will not detect a BGR/RGB swap. We keep the channels in BGR anyway, like the weights.

## What “works” means

- operator tests: absolute error about 1e-4 against hand-computed values
- clean Latin and Polish print: CER below about 0.25
- three print scans: the Nixon letter, the receipt and the invoice fields outside the table. The number of character errors does not rise above the threshold measured on PP-OCRv6 small. The signature, the stamp and the table grid are not in the reference. The joined invoice text has the seller column before the buyer column, and the price on the receipt stays in the item row. The invoice with ruling lines has an item row in which the name and the gross amount are in different cells, and the rates 23% and 5% in one grid. The receipt, the letter and the invoice drawn without ruling lines have an empty list of tables
- the timing harness prints milliseconds and declares no threshold until the measurement is in the documentation
- the held-out `bench/` set (documents outside tuning, references transcribed by hand): CER and words for both profiles, and for Tesseract and RapidOCR on the same files, are in `docs/benchmark.md`. A rule that hurts on this set is dropped or stays behind a flag
